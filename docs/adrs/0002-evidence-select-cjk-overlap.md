# ADR-0002 · 查询侧词面匹配的 CJK bigram 口径（evidence_select）

- **日期**: 2026-08-05
- **状态**: accepted（2026-08-05 evidence_select 课真实链路验收通过：18 边界
  测试 + demo_evidence_select 四步全过，中文 overlap 0.650 > 0 实证）
- **关联**: 重建课程 P7 第四课 `src/paper_rag/rag/evidence_select.py`；
  [ADR-0001](0001-fts5-cjk-bigram.md)（FTS5 索引侧的 CJK bigram 决策，本 ADR
  把同一口径延伸到 RAG 层的查询侧打分）；全局约束"重建版必须支持中文论文"
  （LEARNING_STATE.md, 2026-08-01）

## 背景：我们碰到了什么问题

`evidence_select.py` 把检索宽窗（intent 三档 5/10/15 块）确定性收敛为 ≤4 块可
引用证据。打分四层中，**词面重叠（lexical overlap）是平局裁决层**：模型分
（rerank/RRF）相近的候选块，靠"问题与块文本的 token 交集比例"分出先后，权重
0.2。动手重建前核对基准实现，发现两个中文盲区：

### 问题 1：`_TOKEN_RE = r"[a-z0-9]+"` 对中文问题恒得 0（致命）

基准的 token 化只认小写拉丁字母与数字。中文问题一个 token 都抽不出来，
`q_tokens` 为空集，`_lexical_overlap` 直接返回 0.0——**所有候选块的 overlap
恒等，平局裁决层对中文问题整体失明**，选块退化为纯模型分排序。

混排问题更隐蔽："RAG 的召回率是多少" 只抽出 `rag` 一个 token，重叠算得出数值
但严重失真——问题的中文主体（召回率）完全不参与匹配，一个只提到 RAG 却与
召回率无关的英文块会拿到满额重叠分。

### 问题 2：`_SECTION_HINTS` 提示表全英文

章节提示层（`abstract/method/result` 等出现在 section/title 时 +0.03）对中文
论文的"摘要/方法/实验/结果"一个都打不中，中文块永远拿不到这层加分。单独看
权重很小，但与问题 1 叠加后，中文块在平局场景下的两层裁决全部失效。

## 决策：技术选型

### 选型 1：token 化改为"拉丁词 + CJK bigram"并集

新增 `_tokens(text) -> set[str]`：

- 拉丁侧维持基准 `[a-z0-9]+`（小写化后提取），英文行为不变；
- CJK 侧提取连续汉字 run，按相邻二字对展开（`反思令牌` → `{反思, 思令, 令牌}`），
  单字 run 退化为单字 token（不产生空集）；
- **问题侧与块文本侧用同一函数**，两侧自动对齐；
- overlap 公式不变：`|q ∩ text| / |q|`。

**与 ADR-0001 的口径一致性**：bigram 粒度、单字退化 unigram 的处理与 FTS5
索引侧决策相同。稀疏检索层与证据选择层对"中文如何词面匹配"从此是同一答案，
评测时两层的行为可互相印证。

**否决的备选**：

- **jieba 词典分词**——需新增依赖（违背"与基准同依赖"约束），学术术语误切多；
  ADR-0001 已否决过一次，理由在查询侧同样成立。
- **逐字 unigram**——单字判别力弱：`网络` 与 `经网` 在 unigram 下都命中
  `网`，误召回抬高所有块的 overlap，平局裁决反而失真。
- **复用 `retrieve.fts5.segment_cjk`**——口径相同，但它产出面向 FTS5 索引的
  空格分隔字符串，这里需要集合；且 `rag` 层的纯打分函数不应耦合某个稀疏后端
  模块（sparse_backend 可配置为 rank_bm25，届时该导入就名不副实）。两处各自
  ~8 行、口径由本 ADR 与测试钉住，重复成本低于耦合成本。

### 选型 2：`_SECTION_HINTS` 增中文条目

追加 `摘要/引言/绪论/方法/实验/评估/结果/结论/总结` 九个条目，匹配逻辑不变
（小写化子串 `in`；CJK 不受 `lower()` 影响）。条目与切块层 `sanity.py` 的中文
章节关键词表（P4 课）取交集口径，不引入新的章节命名假设。

### 保持基准、不做的事

- **打分权重（0.2 / 0.03 / 0.001）不进配置**：算法常数而非运维可调项，进
  配置反而鼓励无评测依据的瞎调；将来若要调，应走评测课拿数据说话。
- **`max_chunks=4, max_per_paper=2` 保留为签名默认**：它们是公开 API 的默认
  参数而非埋起来的常数；是否配置化推迟到 qa_agentic 课由调用方决定。
- trace 的 `chunk in selected` 字典相等比较照抄基准（同内容块会同标
  selected 的理论边界，真实链路 chunk_id 不同不触发），记账不修。

## 已记账边界

- **单字 CJK 问题 overlap 恒 0**：问题 `图` 的 token 集 `{图}` 与文本侧
  bigram 集（`{图神, 神经, …}`）无交集。与 ADR-0001 的"bigram 索引无
  unigram"同口径——单字查询本就落在词面匹配盲区，由稠密/rerank 分数兜底。
  专测 `test_single_cjk_char_question_no_crash` 钉死该行为并写明缘由。
- 兼容 ADR-0001 的既有记账：两个稀疏后端 zh 粒度不一致（fts5=bigram,
  rank_bm25=unigram）仍留待评测课统一；本 ADR 使 evidence_select 站在
  bigram 一侧。

## 后果

- 中文问题的平局裁决层从整体失明恢复为可用：真实链路验收中，中文问
  `综合能源服务里区块链的网络架构是怎样设计的` 的 top-1 候选
  overlap=0.650（基准恒 0），且选中块 `section=摘要` 同时吃到中文章节加分；
  英文问 top-1 overlap=0.750，英文行为与基准一致。
- 中文候选的 `selection_score` 与基准不再逐字节可比（overlap 从 0 变为非 0）；
  英文候选逐字节一致。等价标准按课程约定取"运行行为正确"。
- token 集合较基准增大（CJK bigram），但 evidence_select 每次只处理 ≤15 块的
  宽窗，集合运算在微秒级，无性能影响。
